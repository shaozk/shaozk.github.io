初试 herdr 工具，我有了使用 herdr 替代 tmux 的想法。下面从学习成本、功能覆盖和新特性三个方面说明我为什么这样做。

1. 学习成本

    作为一个务实派，使用一个新工具首先需要考虑的是学习成本，毕竟程序员都是“懒惰”的。而 herdr 的默认按键绑定和 tmux 基本一样，从 tmux 切换过去非常丝滑。

    并且，herdr 提供了更丰富的按键提示功能，忘记了马上可以查看提示（我之前使用 tmux 可没少查按键）。

2. 功能覆盖

    能使用的功能必须是一样的，我可不想丢了西瓜捡了芝麻。

    我用到的 tmux 功能很少，如：新建 window 和 pane，在不同的 window 和 pane 之间切换。对于这些基本窗口管理功能，herdr 全部都提供了。

    或许有些 tmux 具有的功能 herdr 没有，不过那些我没用到过，也不知道其存在。

3. 新特性

    herdr 还提供了一些很棒的特性，太多了我挑选几个令我印象深刻的功能举例。

    复制模式：我以前想要复制终端打印的内容，需要使用鼠标选中，然后进行拷贝，十分糟糕。而 herdr 直接支持用 vim 风格方式复制终端内容。

    插件系统：扩展更丰富的功能，如 herdr-plus 插件，支持自定义快速动作和项目。

当然还有其他很多考虑的点，比如代码是否开源，社区是否活跃，对于 herdr 来说，这些都是肯定的。

总结，herdr 不仅仅是用 rust 重写多窗口管理工具这么简单，而是真正解决很多痛点问题。具有如下优点：

* 极少学习成本，对于学习 tmux 的人来说，无缝切换
* 操作更加简单，更多提示信息帮助你使用
* 支持终端复制模式，自定义插件扩展，更丰富的功能 
* 更好的 Agents 交互（对我暂时没用）

tmux 无疑是一款十分优秀的多窗口管理工具，不过后面会减少使用了，因为我有了 herdr。
