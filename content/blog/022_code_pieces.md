> 注意：个人代码片段记录工具。

## 有过这样一个想法

一种类似单词卡片的代码卡片工具，支持在 PC 端记录代码片段，然后在手机端查看。可以随时随地查看这些代码片段了（即使在上厕所，当然需要网络）。

当时还启动了一个名为 pocket-code（朋友帮忙，意指口袋代码）的个人项目，不过最后不了了之了。其中很重要的一个原因是：我要想后端内容——用户管理和代码数据库设计，还要做前端实现—— Web 网页和手机端 App。

这需要的技术栈太多了，我的兴趣还不足以支撑去完成全部内容。

## 有这样一个习惯

我会写一些小代码测试片段，用于验证某个函数或特性。不管是第一份 C 语言的工作，还是后面学习 C++、Qt、Python 等。

不过当时没有将其进行管理，永远保存在了公司电脑上（对我来说是如此，但实际上被清空成 0x00000）。

于是我痛定思痛，专门 Create 了一个用于存放我示例代码的仓库 [pieces](https://github.com/shaozk/pieces)，放在 GitHub 上还能防止本地误删（血与泪的教训）。

## 等等？

GitHub 仓库支持部署静态网页，在 PC 和手机都可以访问。代码数据即源代码内容，只要让其以卡片形式显示，我的需求不就实现了么。

并且当我在仓库中添加代码并上传到远程仓库时，能自动触发 GitHub Action 完成静态页面更新，不需要我做任何多余动作。

简直不要太完美。有了想法，接下来就只剩实现了。

## 谁来实现？

没有 Coding，只有 Vibing。

感谢 AI 的开发者们，你们创造了 Eazy 生活。

## 关于开源

我本意是不打算开源的（也没必要），因为这不是一个通用的工具，只对我自己有用。

但奈何 GitHub 仓库不设置成 Public 可见的话，无法正常发布网页，要怪就怪 GitHub。

## 后续问题

* 代码量太多导致无法仓库无法存储？

  我想不可能。

* 分类太少不便于查找？

  确实有这个问题，目前只按照源代码文件夹（是编程语言名）进行分类，未来或许可以增加更强大的标签管理。

* 交互？

  目前只有最简单的交互，看上去够用，根据后续的体验再看要不要修改吧。
